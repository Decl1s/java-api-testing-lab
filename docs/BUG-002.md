# BUG-002: принятие лишних данных после JSON

Статус: исправлено; регрессия TC-20. Объект проверки — учебный локальный стенд, не внешний продукт. Воспроизведено на `bb1608241dd554ec54b994cf51125aa8c642837d`.

Условия: обычный режим, пустое хранилище, POST /jobs с X-Api-Key: demo-token и Content-Type: application/json.

Тело запроса:

```text
{"filename":"sample.pdf","sizeKb":12} {}
```

Ожидалось: 400 invalid_json, без создания задания. Фактически: 201 и созданное задание. Варианты с ` true` и ` garbage` после объекта также давали 201. Все три регрессионных варианта до исправления падали с expected 400, actual 201.

Причина: ObjectMapper.readTree по умолчанию завершал чтение после первого корневого значения. Включён FAIL_ON_TRAILING_TOKENS, чтобы парсер проверял остаток тела. Ошибка попадает в существующую ветку 400 invalid_json до изменения хранилища.

Проверка: TC-20 проверяет три недопустимых окончания, отсутствие задания после отказа и успешный следующий запрос с допустимыми конечными пробелами. TC-18 продолжает проверять большие тела с конечными пробелами на границе 8192 байта.

Воспроизведение и исправление подготовлены с помощью AI.
