# Тест-план

Цель: проверить HTTP-контракт подачи, чтения и отмены заданий.

Главные риски: принятие некорректного размера; доступ без ключа; потеря состояния после отмены; влияние одного задания на другое; неверная диагностика запроса по коду ответа.

Приоритет P1: создание/чтение, авторизация, размер, отмена, независимость заданий. P2: формат JSON, тип содержимого, длина имени, неизвестное задание, неподдерживаемый метод, ограничение тела.

Методы: функциональные black-box проверки через HTTP, классы эквивалентности, граничные значения, переходы состояний QUEUED → CANCELLED. Код фикстуры доступен для диагностики. Это не интеграционный тест нескольких внешних сервисов.

Среда: Java 17+, Maven, loopback HTTP, хранилище в памяти. Новый сервер для каждого теста. Данные: синтетические имена файлов и размеры; никаких данных заказчиков.

Выход: обычный набор проходит без failures/errors; демонстрационный дефект вызывает ожидаемые падения; результат записан в отчёте. В CI дополнительно проверяется среда Java 17 после публикации.

Вне области: нагрузка, БД, UI, реальная антивирусная проверка, полноценная безопасность, гонки параллельной отмены.
